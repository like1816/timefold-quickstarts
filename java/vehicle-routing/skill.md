## The experiment loop

实验在专用分支上运行...

LOOP FOREVER：

1. 查看 git 状态：我们所在的当前分支/提交
2. 通过直接修改代码来调整，提出一个实验想法
3. git commit
4. 运行实验...
5. 读取结果...
6. 如果输出为空，则运行崩溃...
7. 将结果记录到 tsv（注意：不要提交 results.tsv 文件，让它不被 git 跟踪）
8. 如果指标改善，则“推进”分支，保留 git commit
9. 如果指标相同或更差，则 git reset 回起点

这个想法是，你是一个完全自主的研究者，尝试各种东西。如果它们有效，就保留。如果没有，就丢弃。你正在推进分支，以便你可以迭代。如果你觉得自己在某种程度上陷入困境，你可以回退，但你应该非常非常谨慎地（如果有的话）这样做。

**超时**：每个实验应该总共花费大约...。如果运行超过...，杀死它并将其视为失败（丢弃并恢复）。

**崩溃**：如果运行崩溃（OOM、bug 等），请使用你的判断：如果是愚蠢且容易修复的东西（例如拼写错误、缺少导入），修复它并重新运行。如果想法本身从根本上被打破，就跳过它，在 tsv 中将状态记录为 "crash"，然后继续。

**永远不要停止**：一旦实验循环开始（在初始设置之后），不要暂停询问人类是否应该继续。不要问“我应该继续吗？”或“这是一个好的停止点吗？”。人类可能睡着了，或者离开电脑，期望你继续工作*无限期*直到你被手动停止。你是自主的。如果你没有想法了，更努力地思考 — 阅读代码中引用的论文，重新阅读范围内的文件以寻找新角度，尝试结合之前的接近成功，尝试更激进的架构变化。循环运行直到人类中断你，就这样。

举个例子，用户可能在睡觉时让你运行。如果每个实验大约需要...，那么你每小时可以运行大约...，在普通人的睡眠期间总共大约...。然后用户醒来就有实验结果了，都是在他们睡觉时由你完成的！
